CANDIDATE ADMISSION · AUDITED 2026.08.03

不是发现了就接入，
而是过关后才靠岸。

扩容候选来自公开目录，但公开目录只负责“发现”，没有注册表写权限。系统需要经过静态筛选、专用凭据、网络安全检查和真实最小请求；最终只把实测成功的模型加入本地注册表。

公开目录发现有效本轮实时发现 44 家 / 322 个显式零单价模型
安全准入链路有效58 项聚焦测试全部通过
V4 Flash 本机实调用3 成功 / 2 失败另与 Cloudflare 服务器视角交叉核对
“永久免费”证明不能据此断言仍需官方条款、额度和有效期证据

结论：当前机制能有效证明“这个凭据下，这个模型此刻能返回最小 OpenAI Chat 响应”，也能阻止未经测试的候选静默接入；它不能单独证明长期免费、流式输出、工具调用或全部协议能力。

分场景结论

本机 CLI：NVIDIA NIM 与 OpenCode Zen 当前实测可用，前者需 Key，后者 Keyless 但限时。Cloudflare 服务器：两者当前分别遇到 529 与 429，不能标成服务器稳定可用；SenseNova 双视角成功，但免费条款未核实。当前没有一个渠道同时满足“官方免费证据 + 本机成功 + Cloudflare 成功”。

DeepSeek V4 官方发布模型身份、参数、1M 上下文与开放权重 DeepSeek 官方价格官方 API 按 Token 计费 NVIDIA NIM 模型页Free Endpoint、模型 ID 与 API 示例 OpenCode Zen 官方说明独立免费 ID 与“限时免费”声明 OpenRouter 免费索引页保留为冲突证据；实时 API 本轮返回 404 DeepSeek 官方 Hugging FaceMIT 权重与本地部署方法

延迟均为单次最小请求观察值，不是性能排名。本机结果来自开发机直连；Cloudflare 结果来自公开状态 API 最近快照，两者网络出口、地区与限流策略不同。Key 从私有配置读取，页面、日志和测试输出均不包含 Key 或响应正文。渠道政策会变化，本站需要持续复核。

TRUST BOUNDARY

“接入成功”分成三层，不要混为一谈。

L1
协议准入

真实最小 Chat Completions 请求返回非空助手文本。自动收录达到的是这一层。

自动
L2
运行可用

接入后由 Live Probe 持续记录模型可用性、HTTP 状态和延迟；公开状态页使用 Cloudflare 服务器端探测，与用户本机无关。

持续探测
L3
免费资格与完整能力

需要官方证据 URL、核验时间、失效时间、额度/地区/绑卡条件，以及流式、工具、多模态等专项测试。

待增强

  • 凭据值不写 discovery.json 或 registry.yaml
  • 自动接入默认关闭，需要显式 opt-in
  • 单个周期默认最多测试 5 家、每家 3 个模型

OPERATOR GUIDE

如何安全地验证并接入候选

下面命令都在运行 open-free-router 的机器执行。先只读发现，再为你认可的候选单独配置凭据。

01 · 只读发现open-free-router discover --dry-run

联网读取候选，但不写快照、不修改注册表。

02 · 专用授权export OFR_PROVIDER_API_KEY="你的密钥"

需要鉴权时使用页面输出的准确变量名；实测 Keyless 则不发送 Authorization。

03 · 测试不收录open-free-router discover --test

保存私有验证快照，检查 ready / failed 等状态。

04 · 明确收录open-free-router discover --test --adopt

只将本轮成功模型写入注册表，并保留备份。

默认配置
discovery:
  enabled: true
  interval_hours: 24
  auto_test: false
  auto_adopt: false
  max_providers_per_cycle: 5
  max_models_per_provider: 3

推荐：先保持 auto_adopt: false。候选完成官方免费条款核验、连续可用性探测和所需能力测试后，再决定是否长期自动收录。

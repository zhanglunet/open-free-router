SYSTEM ARCHITECTURE

一个本地端口，九个客户端，十一家免费上游。

open-free-router 在本机架起一座自由港：单个 127.0.0.1 端口听懂三种 HTTP 协议与一条 MCP 通道，再用虚拟模型、可解释评分、三层故障隔离与首字节前安全 fallback，把 9 个终端客户端的请求路由到 11 家免费上游。上游密钥只存本机，响应逐行真流式透传。

ROUTING & RESILIENCE

智能选择，安全降级。

v0.3.0 不再只是“模型 ID 到上游 URL”的静态映射。路由计划、免费证据、额度、运行状态和本机真实指标共同决定候选；每个决定都能解释，也能一键恢复为确定性顺序。

01 · VIRTUAL MODELS

四个虚拟入口

auto、auto/coding、auto/fast、auto/free 根据能力和证据生成候选，显式模型默认不静默换模。

02 · EXPLAINABLE SCORE

六因子可解释评分

健康、成功率、延迟、额度、能力与免费证据统一归一化；总分、权重、贡献和缺失值来源全部可查。

03 · THREE LEVELS

三层故障隔离

Provider、匿名 Key 槽和 Model 各自熔断/冷却，单个模型或凭据失败不会拖垮整个提供商。

04 · QUOTA AWARE

额度与多 Key 选择

归一化 RateLimit 与 Retry-After，优先选择当前可尝试、较早恢复且近期成功的匿名凭据槽。

05 · SAFE FALLBACK

首字节前安全 fallback

只有尚未向客户端发送响应时才重试候选；首字节后禁止重放，避免重复工具调用、重复计费或拼接输出。

06 · LOCAL ANALYTICS

最小化本机可观测

usage.db 只保存状态、耗时、Token 和 fallback 次数；不保存 Prompt、响应、工具参数或原始请求 ID。

REQUEST LIFECYCLE

一次请求的完整旅程。

从客户端发出到流式返回，一共十步。上游凭据只在本机执行阶段短暂使用；失败只允许在首字节前换候选。

SECURITY BOUNDARY

密钥不出本机。

安全边界画在 127.0.0.1：上游凭据、客户端、公网三者被代理严格隔离。

01

密钥仅存本机

上游 Provider Key 只写入本机 registry.yaml，文件权限 0600，永不进入任何客户端配置。

02

客户端零上游凭据

sync 只下发本地 proxy token。对客户端而言上游并不存在，只有 127.0.0.1:8337。

03

公开数据脱敏

Live Probe 结果与公开目录 API 在输出前剥离全部凭据字段，只保留能力与状态。

04

默认仅回环监听

代理与仪表盘默认绑定 127.0.0.1，不暴露局域网；鉴权采用恒定时间比较。

05

运行状态最小化

runtime-state.json 与 usage.db 使用匿名槽位和字段白名单，不保存内容数据。

06

MCP 最小权限

默认 8 个查询、推理和只读诊断工具；刷新与同步必须由所有者显式启用。

今天的大模型世界有一个很有意思的矛盾：一边是越来越多能力不错的模型开放免费额度，另一边是普通用户很难真正把这些资源用起来。

01 · THE REAL PROBLEM

免费模型很多，但“能找到”和“能用上”是两回事。

你可能在社区看到某个平台提供免费模型，注册后才发现需要特定地区、信用卡或邀请资格；也可能好不容易拿到 API Key，模型名称、接口格式和工具调用又与现有客户端不兼容。今天可用的免费额度，明天可能限流；静态清单里写着“免费”，并不代表你的账户此刻真的能完成一次请求。

更麻烦的是，这些变化分散在不同厂商、文档和社区讨论里。开发者为了让 Codex、Claude Code 或 OpenCode 换一个模型，往往要反复修改配置、复制密钥、猜测模型 ID，然后在一串难懂的错误里寻找原因。

免费不应该意味着低效、盲选和碰运气。真正需要的是一条持续更新、能够验证、随时可切换的航路。
02 · WHAT IS FREE MODEL PORT

模力自由港，不是又一个模型平台。

它是一套开源、本地优先的免费大模型路由与发现系统。它不生产模型，也不替你托管上游密钥，而是把散落在不同厂商的免费资源整理成一张航图：哪些是正式接入的模型，哪些只是公开目录中的候选，哪些经过真实请求验证，哪些因为密钥、额度或上游状态暂时不可用。

安装后，你的 AI 客户端只需要面对一个本地地址。模型路由、协议差异、流式响应、工具调用和客户端配置同步，都由自由港在本机处理。想换模型时，不必重新改一套上游配置；想检查可用性时，也不必逐个打开控制台试错。

一句话理解

它把“寻找免费模型 → 验证能否运行 → 比较能力 → 接入开发工具”连成了一条可重复、可审计的流程。

03 · SEVEN CORE SERVICES

七项服务，让免费模型真正进入日常工作流。

01

持续发现新的免费提供商

模型雷达定时扫描公开目录，筛选明确零价格、公开 HTTPS 且尚未登记的候选。候选不会因为“看起来免费”就直接进入正式路由。

02

用真实请求验证可用性

Live Status 会向真实上游发送最小请求，只记录成功状态、延迟和脱敏错误。你看到的“可用”，来自实际响应证据，而不是宣传页或静态标签。

03

中文比较模型与厂商

公开模型雷达集中展示上下文窗口、最大输出、推理能力、工具调用、速度定位、厂商背景和 API Key 获取方法，帮助你根据任务选择，而不是只看模型名字。

04

一个端口接入九类客户端

Codex、Claude Code、OpenCode、Kimi CLI、OpenClaw、WorkBuddy、Hermes、Pi 和 OMP 都能从同一注册表同步。Responses、Anthropic Messages、OpenAI 兼容接口与 MCP 通道同时可用。

05

本地控制台统一管理

全中文仪表盘提供运行总览、提供商与模型筛选、真实实测、候选雷达、客户端一键同步和系统配置。最近实测结果在服务重启后仍可查看。

06

可解释智能路由与安全降级

虚拟模型按能力、健康、成功率、延迟、额度和免费证据选择候选。Provider、匿名 Key 槽与模型三层隔离，只在首字节前 fallback，流式开始后绝不重放。

07

隐私优先的本机使用分析

成功率、p50/p95、Fallback 挽回与 Token 统计只保存在本机；Prompt、响应正文、工具参数、API Key 和原始请求 ID 都不会进入数据库。

模型研究与评测者

想快速比较不同模型的上下文、推理、工具调用和真实可用状态，减少重复环境配置。

希望上游密钥由本机掌握，公开网站只呈现脱敏目录和状态，不上传私有注册表。

05 · LOCAL FIRST

为什么我们反复强调“本地优先”？

因为一个统一路由器很容易变成高权限中心：它能接触多个提供商的 API Key，也能改写开发客户端配置。模力自由港把这个控制面留在你的电脑上，默认只监听 127.0.0.1。客户端拿到的是本地代理 Token，不需要接触任何上游密钥。

公开网站发布的是经过脱敏的模型元数据、候选资料和验证状态；本地 registry.yaml、API Key、代理 Token 和响应正文不进入公开目录。候选自动接入也不是默认行为，只有在公开 HTTPS、协议兼容、专用环境变量和真实响应全部满足时，才允许进入可信路由。

上游密钥留本机候选与正式目录隔离写操作需要本地令牌公开数据持续脱敏

ONE-CLICK INSTALL

一键安装

脚本会克隆 GitHub 仓库、创建隔离的 Python 虚拟环境、安装 CLI，并可同时生成 Codex profile。

建议先检查脚本

最稳妥的做法是先下载、阅读，再执行。脚本不会收集或上传 API Key。

当前需要仓库读取权限

维护仓库目前是私有仓库，安装脚本执行克隆前，请先用 gh auth login 或其他方式为 Git 配置读取权限。公开安装页面与脚本不等于源码仓库已公开；没有权限时克隆会失败。

推荐：下载、检查、安装
curl -fsSLo /tmp/open-free-router-install.sh https://oaf.asia/install.sh
less /tmp/open-free-router-install.sh
bash /tmp/open-free-router-install.sh --codex --auto-discovery
快捷：安装、配置 Codex 并启用模型雷达
curl -fsSL https://oaf.asia/install.sh | bash -s -- --codex --auto-discovery

为什么要用独立 profile？

第三方模型元数据与 OpenAI 官方模型不同；隔离 profile 能避免第三方 provider、模型目录和 MCP 设置影响你的正常 Codex 会话。

MCP SERVER

MCP 宿主接入

路由器内置 MCP（Model Context Protocol）stdio 服务器，任何 MCP 宿主（Claude Code、Codex、Kimi CLI 等）都能以标准协议查询模型、发起推理并读取脱敏诊断。会修改状态的刷新与同步工具默认隐藏，避免 Agent 获得不必要的写权限。

  1. 注册到 Claude Code（用户级）
    claude mcp add --scope user open-free-router \
  -- open-free-router mcp
  2. 或打印通用配置片段
    open-free-router mcp --print-config

    输出可直接粘贴到 .mcp.json / ~/.claude.json 的 mcpServers 条目。

  3. 在会话中使用

    例如让 Agent 调用 list_models 挑选模型，用 explain_route 检查候选原因，或用 chat 把子任务转发给免费模型执行。

MCP Tools

list_models
按 provider / 工具能力过滤模型清单
list_providers
提供商与密钥状态（不含密钥值）
get_status
代理/仪表盘可达性与注册表统计
chat
经本地代理向免费模型发起真实推理
explain_route
离线解释候选、过滤和评分，不消耗额度
get_resilience
Provider / 匿名 Key 槽 / Model 保护状态
check_quota
脱敏额度、重置时间与免费证据
get_metrics
本机成功率、延迟、Fallback 与 Token 聚合

默认 8 个工具。设置 mcp.allow_write_tools: true 后才增加 refresh_models、sync_clients，合计 10 个。传输：stdio · 按行 JSON-RPC 2.0 · 协议版本 2024-11-05 ~ 2025-06-18。

VERIFIED AUTO-ADOPTION

自动测试与安全接入

自动接入不会使用未知凭据，也不会把“目录中价格为 0”直接当作可运行。

发现候选→识别声明凭据→公网 HTTPS 检查→真实最小请求→只接入成功模型
一次性测试并接入
export OFR_GITHUB_MODELS_API_KEY="专用于该提供商的凭据"
open-free-router discover --test --adopt \
  --max-providers 5 --max-models 3
open-free-router sync --agent codex

程序不会自动读取 GITHUB_TOKEN 等通用高权限变量。每个候选生成独立的 OFR_提供商_API_KEY 变量名；registry 只保存这个变量名，不复制变量值。要启用守护进程自动接入，在 config.yaml 的 discovery 下设置 auto_test: true 和 auto_adopt: true。

CLI REFERENCE

完整 CLI 接口

serve

启动代理、管理页、刷新与发现调度器。

setup

交互式填写已登记供应商密钥。

sync --agent claude,codex,…

同步九个客户端：pi、omp、opencode、hermes、codex、claude、kimi、openclaw、workbuddy。

mcp [--print-config]

MCP stdio 服务器；或打印宿主注册片段。

status [--json]

一屏健康摘要：注册表、密钥、端口可达性。

doctor [--json]

体检安装与路由配置：定位 YAML 路径、错误代码并给出修复命令。

models [--json]

列出全部注册表模型与能力标记。

route explain MODEL [--json]

离线解释候选顺序、过滤与评分，不发起推理。

resilience [--json]

查看提供商、凭据槽和模型的运行时保护状态。

resilience reset --provider NAME

精确重置提供商或单模型保护状态。

metrics [--days 30] [--json]

查看本机成功率、p50/p95、Fallback 与 Token。

metrics --export json|csv

用字段白名单安全导出本机聚合统计。

protocols [--json]

输出 11 个提供商 × Chat/Responses/Messages 兼容矩阵。

discover --test --adopt

只接入真实请求成功的候选模型。

refresh [--source NAME]

刷新已登记供应商模型列表。

add NAME --base-url URL

手工添加提供商和模型。

token

供命令式认证读取本地代理令牌。

ui

单独启动本地管理页。

架构、状态文件、请求时序和安全边界见 系统架构页；完整协议验收口径见仓库中的 docs/protocol-capability-matrix.md。

TROUBLESHOOTING

常见问题

Address already in use

8337 已被占用通常表示 open-free-router 已经运行。先执行 lsof -nP -iTCP:8337 -sTCP:LISTEN，不要启动第二个实例。

模型出现在列表里，但工具调用失败

“可见”不等于“工具已验证”。模型雷达会分别显示推理和工具能力；自动发现接入默认不会宣称工具调用已验证。

Codex 看不到第三方 provider

provider 必须放在用户级 profile，不能放项目级 .codex/config.toml。重新执行 open-free-router sync --agent codex，并用 codex --profile open-free-router 启动。

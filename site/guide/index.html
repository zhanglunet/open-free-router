ONE-CLICK INSTALL

一键安装

脚本会克隆 GitHub 仓库、创建隔离的 Python 虚拟环境、安装 CLI，并可同时生成 Codex profile。

建议先检查脚本

最稳妥的做法是先下载、阅读，再执行。脚本不会收集或上传 API Key。

推荐：下载、检查、安装
curl -fsSLo /tmp/open-free-router-install.sh https://oaf.asia/install.sh
less /tmp/open-free-router-install.sh
bash /tmp/open-free-router-install.sh --codex
快捷：一条命令安装并配置 Codex
curl -fsSL https://oaf.asia/install.sh | bash -s -- --codex
1

配置密钥

open-free-router setup

逐个填写已有供应商的 Key；可跳过暂时不用的供应商。

2

启动全部服务

open-free-router serve

同时启动代理 8337、管理页 9057 和定时发现任务。

3

检查健康状态

curl http://127.0.0.1:8337/health

CODEX CLI

Codex CLI 安装与使用

  1. 安装 Codex CLI
    npm install -g @openai/codex
codex --version
  2. 正常 OpenAI 登录（可选）
    codex login

    第三方 profile 使用本地路由令牌；正常 profile 仍可使用 ChatGPT 登录。

  3. 生成隔离的第三方 profile
    open-free-router sync --agent codex
  4. 启动第三方模型模式
    codex --profile open-free-router

    在会话中使用 /model 切换已验证模型。

  5. 命令式调用
    codex --profile open-free-router exec \
  "检查当前仓库并运行测试"

DESKTOP CLIENT

Codex 客户端

当前 Codex 桌面体验位于 ChatGPT 桌面应用。Codex CLI 可以打开已安装的客户端；客户端缺失时会进入安装流程。

用第三方 profile 打开当前项目
codex --profile open-free-router app .

也可以先运行 codex app . 完成客户端安装，再从终端使用第三方 profile 打开项目。CLI 与客户端使用同一套用户级 Codex 配置层。

为什么要用独立 profile？

第三方模型元数据与 OpenAI 官方模型不同；隔离 profile 能避免第三方 provider、模型目录和 MCP 设置影响你的正常 Codex 会话。

VERIFIED AUTO-ADOPTION

自动测试与安全接入

自动接入不会使用未知凭据，也不会把“目录中价格为 0”直接当作可运行。

发现候选→识别声明凭据→公网 HTTPS 检查→真实最小请求→只接入成功模型
一次性测试并接入
export OFR_GITHUB_MODELS_API_KEY="专用于该提供商的凭据"
open-free-router discover --test --adopt \
  --max-providers 5 --max-models 3
open-free-router sync --agent codex

程序不会自动读取 GITHUB_TOKEN 等通用高权限变量。每个候选生成独立的 OFR_提供商_API_KEY 变量名；registry 只保存这个变量名，不复制变量值。要启用守护进程自动接入，在 config.yaml 的 discovery 下设置 auto_test: true 和 auto_adopt: true。

CLI REFERENCE

完整 CLI 接口

serve

启动代理、管理页、刷新与发现调度器。

setup

交互式填写已登记供应商密钥。

sync --agent codex

生成 Codex profile 与模型目录。

discover --dry-run

只扫描候选，不写文件。

discover --test

使用声明的环境变量测试候选。

discover --test --adopt

只接入真实请求成功的模型。

refresh [--source NAME]

刷新已登记供应商模型列表。

add NAME --base-url URL

手工添加提供商和模型。

token

供 Codex 命令认证读取本地代理令牌。

ui

单独启动本地管理页。

TROUBLESHOOTING

常见问题

Address already in use

8337 已被占用通常表示 open-free-router 已经运行。先执行 lsof -nP -iTCP:8337 -sTCP:LISTEN，不要启动第二个实例。

模型出现在列表里，但工具调用失败

“可见”不等于“工具已验证”。模型雷达会分别显示推理和工具能力；自动发现接入默认不会宣称工具调用已验证。

Codex 看不到第三方 provider

provider 必须放在用户级 profile，不能放项目级 .codex/config.toml。重新执行 open-free-router sync --agent codex，并用 codex --profile open-free-router 启动。

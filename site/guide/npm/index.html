QUICK START

安装与首次启动

先确认两个运行时，再安装公开 npm 包。首次运行会安装内置的同版本 Python 源码，通常比后续启动慢。

1 · 环境检查
node --version
python3 --version
npm --version
Python 命令必须可被找到

macOS 自带 Python 可能仍是 3.9。当前 npm 引导器会依次查找 python3、python（Windows 还支持 py -3），其中至少一个必须是 Python 3.11 或更新版本并已加入 PATH。

2 · 全局安装并体检
npm install -g open-free-router
open-free-router --version
open-free-router doctor
1

保存提供商密钥

open-free-router setup

密钥写入本机配置，不交给 npm，也不会上传本站。

2

启动代理与仪表盘

open-free-router serve

代理监听 127.0.0.1:8337，中文仪表盘位于 127.0.0.1:9057。

3

查看模型

open-free-router models

也可运行短命令 ofr models。

HOW IT WORKS

npm 到底安装了什么？

npm 公共包→检查 Python 3.11+→版本隔离虚拟环境→完整 Python CLI
  1. 薄启动器

    Node 只负责环境检查、首次引导和参数透传；路由、协议、注册表、探测与客户端适配仍只有一份 Python 实现。

  2. 按版本隔离

    macOS/Linux 默认位于 ~/.cache/open-free-router/npm/0.3.0；Windows 默认位于 %LOCALAPPDATA%\open-free-router\npm\0.3.0。可用 OFR_NPM_HOME 指定其他位置。

  3. 后续复用

    版本标记和 CLI 可执行文件完整时直接复用，不会每次重新安装。升级 npm 包后，新版本使用新的隔离目录。

LIFECYCLE

升级、重装与卸载

升级到最新公开版本
npm install -g open-free-router@latest
open-free-router --version
open-free-router doctor
只卸载全局命令
npm uninstall -g open-free-router
卸载不会自动删除用户数据

提供商配置通常保存在 ~/.config/open-free-router，npm 运行环境保存在上述缓存目录。这样重装不会丢失配置；如确需彻底清理，请先备份并手工确认目标目录，尤其不要误删整个 ~/.config 或 ~/.cache。

TROUBLESHOOTING

常见问题

先运行 open-free-router doctor，它会检查配置、端口、密钥状态与客户端文件。

提示“未找到 Python 3.11+”

运行 python3 --version。若版本低于 3.11，请从 Python 官方安装新版，并确认新终端里的 python3 指向新版；仅安装但未加入 PATH 仍会失败。

npm 安装成功，但找不到 open-free-router

运行 npm prefix -g 检查全局安装位置，并确认其可执行目录在 PATH 中；也可以先用 npx open-free-router doctor 验证包本身。

首次运行安装失败或被中断

重新执行原命令即可。引导器用锁避免并发写入，失败时会清理未完成的版本环境；网络恢复后会重新创建。

8337 或 9057 端口已被占用

这通常表示服务已经运行。先执行 open-free-router status，不要反复启动；若不是本程序，再用系统端口工具确认占用进程。

npm 包会读取或上传 API Key 吗？

不会。Node 启动器只创建虚拟环境并启动 Python CLI；密钥由本机配置管理。公开模型状态来自服务器端独立探测，与访问者本机配置无关。

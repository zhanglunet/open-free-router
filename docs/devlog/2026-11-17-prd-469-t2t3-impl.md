# PRD-469/T2+T3 开发记录：Retry-After 深度解析（2026-11-17）

> trend issue #2266/#2267。T2（响应头解析）与 T3（正文挖掘）合并交付——060/T4 的响应头解析器已存在，T2 只需补负值钳制；T3 正文挖掘（结构化深度封顶遍历+锚定短语）是增量主体。

## 交付

- `src/open_free_router/retry_after_deep.py`：parse_retry_after_header()（060/T4 共用解析器：delta-seconds 含负值钳 0 / HTTP-date → 秒）+ _search_structured()（深度封顶 6 层遍历搜 retry_after/retry-after/retry_after_seconds/wait_seconds，数组只取首个，非数字跳过）+ _search_text()（白名单正则 try again in/retry after/wait N seconds|minutes，只取前 3 个匹配防恶意塞数字）+ _clamp()（0 ≤ seconds ≤ 86400——畸形/恶意提示无法永久停用密钥）+ parse_retry_after_deep()（三路合并：响应头>正文结构化>正文锚定短语；结果只含数字+来源，正文原文从不保留进日志/trace）。
- `tests/test_prd469_t2_retry_parse.py`：16 例全绿（两形式响应头/嵌套结构化/深度封顶 6 层/非数字跳过/四锚定短语/无关数字不误判/24h 钳制/负值钳 0/header 优先/structured 优先/text 全无 None/结果只含数字/AST 零网络/词表）。

## 首测抓出的实现错误（修正入档）

1. 负值 delta-seconds："-5".isdigit()=False 走了 HTTP-date 分支——补 try/int(value) 钳 0；
2. structured_wins_over_text：正文 JSON 后附文本导致 json.loads 整体失败——改为结构化字段内嵌文本。

# 沙盒使用指南（PRD-079）

沙盒是网关上面的一个可选小工具：你挑一个模型，它让模型按你的任务写一段 Python 代码，然后在**本机一个隔离目录**里把代码跑起来，结果拿回来给你。

打个比方：网关是"电话总机"（负责接哪个模型），沙盒是"代办员"（你告诉它要办什么事，它找模型写代码、替你跑一趟、把结果带回来）。

沙盒**默认关闭**，不影响网关现有任何行为。想用必须显式打开。

## 开启沙盒

1. 在网关配置目录（`~/.open-free-router/`）或当前目录下新建 `sandbox.toml`：

```toml
[sandbox]
provider = "local"      # 本期只有 local（本机跑）和 none（关闭）
network = true          # 必填：local 后端无法真正隔离网络，
                        # 设为 true 表示你已知情并接受
default_models = ["AI/Qwen3.8-Flash-Next"]
timeout_s = 120         # 单次代码执行超时（秒），超了杀整个进程树
```

2. 跑起来：

```bash
open-free-router sandbox run --model <模型ID> task.txt
# 或从管道读任务：
echo "把 1 到 100 的质数列出来" | open-free-router sandbox run --model <模型ID> -
```

3. 常用子命令：

| 命令 | 作用 |
|---|---|
| `sandbox run --model ID [--models a,b,c] [--timeout S] [--network] <文件\|->` | 跑一段任务，打印 JSON 结果（exit_code / stdout / stderr / duration_ms / timed_out / 换模型记录） |
| `sandbox config` | 打印当前生效的 `sandbox.toml`（token 等敏感键已脱敏不显示） |
| `sandbox models` | 列出网关里的可用模型，方便挑 `--model` |

`provider = "none"`（或没有 `sandbox.toml`）时，`sandbox run` 会直接提示"未启用"并退出。

## 指定模型

- `--model <ID>`：只用这一个模型。
- `--models a,b,c`：按优先级列多个，逗号分隔，先后即优先级。
- 都不传：读 `sandbox.toml` 里的 `default_models`。
- 模型 ID **原样透传**给网关，沙盒层不做任何改写、不参与网关选路——你说用谁就用谁。

## 失败策略（换模型规则）

模型**自己**出问题时才换模型，规则如下：

| 失败 | 处理 |
|---|---|
| 429 / 5xx / 超时 / 连不上 | 换列表里下一个模型；换之前指数退避等一会儿 |
| 404（模型不存在） | 跳过这个模型，立刻换下一个（不等） |
| 401 / 403（key 或权限） | **整个列表直接停，报错**——key 坏了换模型也没用，不烧额度 |
| 400（请求本身有问题，如超长） | **不换模型，直接返回**——换谁都一样 |

**代码**出问题（非零退出、断言失败、超时被杀）**不换模型**——代码写错了，换再贵的模型也一样，结果里直接给你退出码和报错信息。

**双封顶**（防烧额度）：`max_model_retries`（默认 3，含第一次）+ `total_budget_s`（默认 300 秒，从第一次调模型到结束的总时间）。哪个先用完就停，报错里写清是"模型都试完了"还是"预算用完了"。

注意：网关内部也有一层"429 同模型重试"（PRD-059），那是网关把一次调用送达上游之前的内部重试；沙盒只在网关最终返回失败后才换模型，两层不重叠。

## 安全边界

**沙盒里能做的**：在本次隔离工作目录内读写文件；用白名单内的环境变量（默认 `PATH`、`HOME`、`LANG`）；输出 stdout/stderr（各最多 1MB，超了截断）。

**沙盒里不能做的**：写工作目录之外的路径（执行前静态检查，直接拒绝）；默认无网络声明（local 后端是本机子进程，**无法真正隔离网络**，`network=false` 会直接报错而不是假装隔离）；执行结束整个进程树清掉，不留常驻进程。

**威胁模型（请知悉）**：local 后端是"防失误、不防攻击者"——能防跑飞、死循环、写错目录，防不住**有意**逃逸的恶意代码。黑名单（`rm -rf /`、反弹 shell、`curl|bash` 等）只是兜底，隔离才是主防。真要防攻击者，等 Docker 后端。

**审计与脱敏**：
- 每次执行记一条审计日志（`~/.open-free-router/sandbox/audit.log`，5MB 轮转留 3 份）：时间、模型、**代码 sha256（只记哈希，不记原文）**、退出码、耗时、是否换过模型。黑名单拦截也会记一条。
- 日志和回显走密钥脱敏：`sk-` 开头的 token、`api_key=...` 这类一律打码，审计记录里含密钥特征的内容直接丢弃不写。

## 资源限制（可选）

```toml
[sandbox]
cpu_limit_s = 600      # CPU 秒数预算，超了进程被杀（0=禁用）
memory_limit_mb = 1024 # 虚拟内存上限 MB（0=禁用）
```

超限被杀会在结果里标记 `resource_exhausted: "cpu" | "memory"`，审计日志里也有。说明：内存限的是虚拟地址空间不是真实内存占用；fork 炸弹靠 `timeout_s` 兜底。

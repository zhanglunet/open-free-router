# Open Free Router 项目开发周报

**周期：** 2026-08-03 至 2026-08-09
**统计口径：** 基于本仓库 `origin/main` 的 Git 历史；统计 52 个非 merge 提交。工作区未提交内容单列为进行中，不计入已交付成果。

## 三句话结论

1. 本周完成 v0.4.0 发布，核心重点从“能转发”推进到“可验证、可解释、可恢复”：模型证据新鲜度、故障隔离、429/403 恢复和新模型实测准入均已落地。
2. 公开模型雷达和站点质量基线完成一轮系统治理：状态降级不再伪装成实时事实，目录改为按模型呈现证据，并加入全站审计、CI、资源指纹和 devlog 规则门禁。
3. 当前最大缺口是变更后的默认 registry 已有 11 个 provider，但协议矩阵测试仍断言 10 个；此外，GLM Coding 与 Codex 直连适配仍在工作区，尚未作为完成项计入发布成果。

## 本周最重要的一件事

完成 v0.4.0 的稳定性与数据可信度收口（`727d296`）。本次发布包含：

- resilience recovery：429 不再仅因错误文案永久禁用 credential；声明式 reset header 生效；403 按模型隔离；terminal 状态具备自动恢复路径；503 能区分缺少密钥与上游失败。
- data freshness：公开 catalog、状态板、模型雷达和 benchmark 使用带时效的模型级证据；过期、缺失、未来时间戳、错误 schema 和降级数据均不再冒充实时可用。
- 新模型准入：`refresh --probe-new` 只有在真实 1-token 请求成功时才采用新模型，并保持 scheduler 默认关闭。
- 发布与工程化：npm bootstrap 包、站点质量门禁、内容 hash 资源指纹和 CI workflow 完成落地。

## 工作进展

### 1. 模型目录与公开数据可信度

- 从 provider 级 smoke test 改为按模型记录与投影证据（`1a4a4ac`、`7323739`）。
- 过期状态、KV miss、未验证模型和 fallback 分支改为显式降级，避免产生“当前可用”“最近检查”等误导性表述（`60481eb`、`67f7da6`、`77ed070`、`678d410`）。
- 上游错误体被截取并脱敏后保留，credential 不进入公开目录或内部快照（`bf8a456`、`91e5e20`）。
- 新增全站审计并修复 58 项发现，随后完成 adversarial audit 的 24 + 18 项收口，以及无障碍和安全 header 修复（`d388da7`、`e0ccbae`、`b63c583`、`79d6639`）。

### 2. 运行时恢复与故障隔离

- 403 仅锁定被拒绝的模型，只有多个不同模型持续拒绝时才归因到 credential（`bd66450`）。
- terminal credential 增加有界恢复探测；429 不再因为 quota/credit/balance 文案直接进入永久终止（`2c87211`、`49822f2`）。
- refresh 对新模型增加可选真实请求验证；路由不可用时返回原因，而不是统一的 opaque 503（`b01939a`、`4f5e7ba`）。
- 复核并修复 stale probe evidence、配置回收范围和 Kimi 可用模型同步问题（`52cd4c8`、`d19008b`、`1ea6670`）。

### 3. 客户端同步与版本交付

- 支持 `sync.exclude` 在裸 `sync`/`serve` 自动同步路径中生效（`bf06fa4`、`3bba07b`）。
- Kimi Code 配置路径迁移，并增加 `--kimi-available-only`，以新鲜实测结果筛选同步模型（`1ea6670`）。
- 发布 v0.4.0，并同步更新 README、英文文档、CHANGELOG、npm 包、协议能力矩阵和公开 devlog（`727d296`）。

### 4. 站点与基准能力

- 增加受保护的内部 benchmark dashboard，修复移动端模型图表和中文排版，并区分本地与服务端 V4 可用性（`ad21fa8`、`737576f`、`84a647f`、`cef4672`、`d1c6b4f`）。
- 增加站点地图、provider 扩展路线图、npm 安装文档和站点质量 PRD。

## 本周最大风险

默认 registry 与协议矩阵测试的 provider 数量契约已经不一致。该问题当前已稳定复现，属于测试门禁缺口；在修复测试或明确矩阵目标前，不应把 Python 全绿状态写入发布结论。

另一个风险是当前工作区存在未提交变更：

- BigModel GLM Coding refresh source、registry 接入和测试；
- `codex-direct-adapter.py` 与 `sync-direct-codex-catalogs.py`；
- README 和既有 refresh 测试的同步修改。

这些改动尚未形成提交，且新增 provider 正是触发当前矩阵失败的直接原因，应先补齐测试契约、运行真实 provider 验证，再决定是否纳入下一版本。

## 下周建议

1. 更新或参数化协议矩阵测试，使 provider 数量与产品目标一致，并补跑完整 Python suite。
2. 为 BigModel GLM Coding 增加真实 endpoint 的受控 probe/兼容性验证，确认 allowlist、模型 ID 和工具调用声明后再提交。
3. 审核 Codex 直连适配器的凭据读取、端口、模型白名单和流式 Responses 转换，补充单元测试与本地 smoke test。
4. 安装 Playwright 后补跑浏览器层站点审计；不要把当前“静态通过”扩写成完整浏览器验收。

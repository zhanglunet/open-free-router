# PRD-202/T1 一句话换模型：意图与回显确认设计

- 关联：PRD-202（trend `adopted/PRD-202-ofr-one-line-model-switch.md`）T1，trend issue #1010
- 日期：2026-10-26
- 状态：设计待评审（T1 验收 = 设计评审通过）
- 前置阅读：`docs/plans/failover-routing-policy.md`（PRD-059/T1，成本维度口径）、`docs/plans/2026-10-25-byos-access.md`（PRD-173，BYOS 接入层）、PRD-201（路由决策可观测，trace 字段口径）

## 0. 一句话结论

给网关加一个"说人话换模型"的入口：用户说"换成便宜的"，系统先**回显**将切换到的后端、预估成本与影响面，用户**确认后**才执行；切换只是一个可回滚的"首选置顶"状态，不改路由策略、不改 BYOS 接入层，全过程留 trace。

## 1. 背景与范围

### 1.1 目标（来自 PRD-202）

- 意图解析：口语意图（便宜/快/质量优先/指定模型名等）→ 候选后端排序
- 回显确认：切换前展示目标后端、预估成本、影响面
- 切换执行：确认后执行，与 PRD-201 trace 打通
- 一键回滚：切回上一后端

### 1.2 非目标（红线，设计层面落死）

- **不做自动切换**：任何代码路径都不得在无人确认时改变当前后端。故障转移（failover）是请求内的既有机制，与本功能无关，不得借道本功能的状态。
- **不改 BYOS 接入层**（PRD-173）：不碰 provider 注册、`byos.enabled`、`byos.prefer_subscribed` 的语义与配置（见 §10）。
- 不改全局路由策略：`routing.policy.weights` 等配置项不在本功能写范围内；意图权重只用于生成一次候选排序提案（见 §4.3）。
- 不做货币价格估算：本网关无价格表，"成本"只有免费额度口径（见 §5.3），不得编造金额。

### 1.3 与相邻工作的关系

| 工作 | 关系 |
|---|---|
| PRD-059 故障转移与成本选路 | 复用其候选排序（三维权重）与成本口径；本功能不改其策略 |
| PRD-201 路由可观测 | 切换事件写入 201 的 trace 体系（§6.4）；字段名以 201/T1 定稿为准 |
| PRD-173 BYOS 接入 | 只读消费候选的 `byos_class` 标注，不改接入层（§10）；其 T4 在途 PR #84/#85 与本设计无文件交集 |
| PRD-079 沙盒层 | 沙盒的模型切换是沙盒内部行为（`sandbox/caller.py`），与本功能互不调用 |

## 2. 现状基线（设计依据，均为当前主分支事实）

- **候选与排序**：`routing.py` 的 `RoutePlanner.plan()` 对虚拟模型（别名）请求做三维打分排序，权重默认质量 0.5 / 成本 0.3 / 延迟 0.2（`POLICY_WEIGHT_DEFAULTS`，可由 `routing.policy.weights` 覆盖）；成本维度是**剩余额度比例**（`costing.py`，实时配额信号优先，文档化 `free_tier` 表只作参考，无数据时按 `missing_default` 不惩罚）；延迟维度用滑动窗口 p50（PRD-059/T3）。显式模型名走 `resolve_explicit()` 不打分。
- **虚拟模型**：内置别名 `auto`、`auto/coding`、`auto/fast`、`auto/free`，外加配置自定义别名。请求按 `model` 字段逐请求规划，**没有"当前后端"这一全局状态**——这是本设计要新增的唯一状态（§3）。
- **候选资格**：`plan()` 已有排除通道：弹性管理器判定全部凭据槽位不可尝试（额度耗尽/冷却中）者排除、要求工具调用的别名排除不支持者、`byos.enabled=false` 者排除（原因 `byos_disabled`）、`auto/free` 要求免费证据为 verified。本设计的候选资格**完全复用**这套排除结果，不另立标准。
- **成本数据**：`docs/provider-profiles.json` 的 `free_tier` 多数数值字段为 null（仓库纪律：无确切数字留空不编造），带 `confidence`（如 `estimated`）与 `updated_at`。回显中的成本预估必须连同这套口径标注一起展示（§5.3）。
- **CLI 形态**：`cli.py` 为 argparse 子命令式（`route explain`、`resilience reset`、`sandbox run` 等均有先例），状态文件有 `~/.open-free-router/` 先例（沙盒审计日志）。本功能入口据此定为 CLI（§3.1）。
- **决策留痕先例**：故障转移决策已落 `usage.db` 的 `failover_decisions` 表；本功能的切换事件按同一思路留痕，但写入 201 的 trace 体系（§6.4）。

## 3. 核心定义与入口决策

### 3.1 入口：CLI 子命令 `switch`（本期唯一入口）

借鉴 cindy 的"一句话入口"形态（§13），落在现有 CLI 上：

```text
ofr switch "换成便宜的"        # 提出意图 → 回显 → 等待确认
ofr switch confirm <确认码>     # 非交互场景的第二步确认
ofr switch cancel <确认码>      # 取消待确认提案
ofr switch status               # 只读：当前切换状态
ofr switch rollback             # 回滚（T4，契约见 §7）
```

- **为什么是 CLI**：仓库既有运维动作（`resilience reset`、`route explain`）都在 CLI；交互确认在终端天然成立；不需要新开网络面。
- **UI（9057）本期不做**：网页确认涉及会话与误触防护，留待后续 PRD；本设计的状态与确认契约（§5、§8）按入口无关方式定义，UI 未来接入时必须复用同一确认门，不得另设直达执行的按钮。
- **MCP 本期不做**：MCP 工具由 agent 宿主调用，"人确认"在该通道无法保证。未来若接入，必须复用 §5 的确认码机制（提案与执行分离），且执行步只能由人触发。

### 3.2 "切换"的定义：别名级的首选置顶（pin）

由于网关逐请求规划、无全局当前后端，本设计把"切换"定义为：

> 为某个虚拟模型别名（默认 `auto`）持久化一个**首选候选置顶**：此后该别名的新请求在 `plan()` 产出候选后，把置顶候选移到第一位，其余候选保持原打分顺序作为故障转移链。

- 置顶不删除其他候选：目标后端故障时仍按既有 failover 链转移，不会因为置顶而单点。
- 置顶目标在请求时若已不合资格（如额度耗尽被排除），该请求自动回落到无置顶的正常排序，并在 trace 中标注 `pin_skipped` 及原因——不静默失败，也不强行使用。
- 显式模型名的请求完全不受置顶影响（它们本来就不走别名规划）。
- 作用域是别名级：对 `auto/coding` 等其他别名不生效，除非用户对该别名单独切换（意图语句可带别名，见 §4.4）。

这一定义是评审决策点 D2（备选：改写别名候选表——会污染用户配置且与自定义别名冲突，不推荐）。

## 4. 意图模型

### 4.1 解析方式：确定性规则，不用 LLM

意图解析用关键词与句式规则实现，**不调用任何模型**。理由：解析必须可复现、可单测（T2 验收就是"示例语句解析正确"）；把一句人话先送给一个收费/免费模型再决定换哪个模型，既绕又不可控。LLM 兜底解析列为非目标，未来如需引入，必须仍产出同一 `IntentResult` 结构并走同一确认门。

### 4.2 意图分类

| 类别 | 触发示例 | 行为 |
|---|---|---|
| `cheap` 便宜优先 | "换成便宜的""省着点用""找个省额度的" | 按 §4.3 便宜权重档排序提名 |
| `fast` 速度优先 | "换个快的""太卡了""要低延迟的" | 按速度权重档排序提名 |
| `quality` 质量优先 | "换个效果好的""要最强的""质量优先" | 按质量权重档排序提名 |
| `free` 免费优先 | "换成免费的""只用免费额度" | 候选先按 `auto/free` 同款规则过滤（免费证据 verified），再按便宜权重档排序 |
| `explicit` 指定模型 | "换成 provider-a/model-x""用 model-y" | `resolve_explicit()` 精确解析（§4.5） |
| `status` 问状态 | "现在用的哪个""当前后端是啥" | 只读回答，不产生提案 |
| `rollback` 回滚 | "切回去""换回上一个" | 转 §7 回滚流程（独立确认） |
| `keep` 保持现状 | "随便""都行""先这样" | 明确不执行，回复当前状态，不产生提案 |
| `unknown` 无法解析 | 无命中且无模型名 | 反问（§4.6），不猜 |
| `ambiguous` 复合/冲突 | "又便宜又快""便宜的质量好的" | 不猜，反问并列出各单维度的提名让用户选（§4.6） |

否定句式归一："不要太贵的"归 `cheap`；"别用 provider-a"属于排除式表达，本期**不实现**（回复说明暂不支持排除式，请改说目标），不猜测其目标。

### 4.3 意图 → 候选排序映射

提名排序 = 对当前别名的候选源（与 `plan()` 同一来源、同一资格排除）做一次**一次性**打分，维度与数据与线上排序相同（质量四因子、成本=剩余额度比例、延迟=滑动窗口 p50），仅权重档不同：

| 意图 | 质量 | 成本 | 延迟 | 备注 |
|---|---|---|---|---|
| 基线（线上默认） | 0.5 | 0.3 | 0.2 | `POLICY_WEIGHT_DEFAULTS`，仅对照 |
| `cheap` | 0.2 | 0.7 | 0.1 | |
| `fast` | 0.2 | 0.1 | 0.7 | 延迟无样本的候选按线上同口径不惩罚 |
| `quality` | 0.8 | 0.1 | 0.1 | |
| `free` | 0.2 | 0.7 | 0.1 | 叠加免费证据过滤 |

权重档为设计默认值（评审决策点 D3），T2 可在不改变结构的前提下校准，并在代码中集中定义、附单测。**权重档只用于这一次提名，不写回 `routing.policy`**，不影响未切换别名的线上排序。

BYOS 候选与普通候选同池排序；`byos.prefer_subscribed` 的既有置顶行为（PRD-173/T3）保持原样发生在 `plan()` 内，本功能不与其叠加改序——提名排序在同一候选源上独立计算，与线上 plan 的最终顺序差异要在回显中可解释（回显给出提名理由档位，见 §5.2）。

### 4.4 作用域（别名）解析

- 语句未提别名 → 默认作用域 `auto`。
- 语句点名别名（如"coding 那个换成便宜的"）→ 作用域为该别名；别名不存在 → 反问并列出现有别名，不猜。
- 一次意图只作用于一个别名；"全都换成便宜的"这类全域表达本期不支持，反问用户逐别名进行（避免一次确认放大影响面）。

### 4.5 指定模型名的解析

- 用 `resolve_explicit()` 的同一套匹配规则（模型 id、`前缀/模型 id`、上游 id 等）精确命中才算解析成功。
- 未命中：反问，并给出注册表中**名称相近的候选清单**供选择——只提示，不自动替用户选最像的那个。
- 命中但当前不合资格（全部凭据槽位被弹性管理器拦截、无凭据等）：不产生提案，回显不可切换的原因（复用 `plan()` 的 rejected 原因口径），状态不变。

### 4.6 歧义与无法解析：只反问，不猜

- **提名分差过小**：第一名与第二名总分差小于 0.05（设计默认值，T2 可校准）时，回显同时列出前两名及其各自的维度档位，请用户回复序号选择；选定后才进入 §5 确认环节。不得以并列第一的注册顺序等隐含规则替用户拍板。
- **复合意图**（`ambiguous`）：并列展示每个单一维度的提名（如"便宜档提名 X / 速度档提名 Y"），请用户选一档，再进入确认。
- **无法解析**（`unknown`）：回复可识别的意图清单（便宜/快/质量/免费/指定模型名/切回去）请用户重述；不做任何状态变更，不产生待确认提案。
- 所有反问路径都不写状态文件、不占确认码。

## 5. 回显确认契约

### 5.1 两步分离（确认门的形态）

提案与执行是两个独立动作，其间不存在任何"顺带执行"的路径：

1. **提案步**（`switch "一句话"` 或显式参数）：完成意图解析与提名，生成提案（payload），写入状态文件的 `pending` 区，输出回显（§5.2）与确认码。**此步绝不修改 `current`。**
2. **执行步**（终端内交互确认，或 `switch confirm <确认码>`）：校验确认码与 payload 一致后才执行 §6。取消（`cancel`、交互答否、输入 EOF、超时过期）一律只清 `pending`，状态不变。

不提供 `--yes` 之类的免确认参数；脚本化调用也必须走两步（设计红线，§9）。

### 5.2 回显必备字段（缺一不可）

| 字段 | 内容与口径 |
|---|---|
| 当前后端 | 当前作用域别名的实际首选：有置顶时显示置顶目标，无置顶时显示"无置顶（按路由打分实时选择）"及最近一次 trace 的首选（若有） |
| 目标后端 | 提名候选的规范 id（`provider/model` 形态）、提供方中文名、BYOS 类别标注（`byos_class`，如订阅类） |
| 提名理由 | 命中的意图类别 + 该意图下目标候选的关键维度档位（如"剩余额度比例同池最高""p50 延迟同池最低"），只说数据支持的结论 |
| 预估成本 | 见 §5.3，必须带口径与置信标注 |
| 与当前对比 | 成本档位与延迟档位的变化方向（更省/相近/更贵等），无数据时明说"无可比数据" |
| 影响面 | 固定文案，逐字包含："切换只对新请求生效，正在进行的请求不受影响；显式指定模型的请求不受影响；目标故障时仍按原故障转移链处理" |
| 回滚提示 | "可用 ofr switch rollback 一键切回" |
| 确认码与有效期 | 确认码（短码）+ 过期时间；过期须重新提案 |

### 5.3 成本预估的口径与偏差标注

本网关**没有货币价格数据**，`free_tier` 表的数值字段多为空。因此回显的"预估成本"定义为**免费额度消耗预估**，且必须：

- 给出**档位**（低/中/高消耗）与可得的实时信号（目标候选当前剩余额度比例，来自弹性管理器的实时配额信号）；无实时信号时只给档位，并注明依据是文档化免费额度（`free_tier`）与该提供方的免费证据状态。
- 标注 `confidence` 与数据日期：直接透传 `free_tier.confidence`（如 `estimated`）与 `updated_at`，并附固定说明："预估口径：按文档化免费额度与当前剩余额度比例估算，实际消耗以各上游控制台为准；免费额度政策会变，数字可能偏差。"
- **绝不输出货币金额**，绝不把 null 字段脑补成数字（仓库既有纪律：无证据不编造）。T2/T3 实现中如发现需要金额化展示，须另行立项补价格数据源，不在本 PRD 内即兴添加。

### 5.4 确认码规则

- 确认码与提案 payload 的哈希绑定：payload 任一字段（目标、作用域、预估快照）变化，旧码即失效。
- 单次有效：执行或取消后立即作废；默认有效期 120 秒（评审决策点 D4）。
- 确认码只出现在提案者本地终端，不写入 trace 明文（trace 只记提案 id，见 §6.4）。

## 6. 切换执行设计

### 6.1 执行步动作（确认后，顺序固定）

1. 读状态文件，校验 `pending` 存在、确认码匹配、未过期、payload 哈希一致；任一不符 → 中止并说明，状态不变。
2. **执行时复检**：重新 `resolve_explicit()` 目标并复查候选资格（凭据槽位可尝试、未被新排除）。提案后目标已不合资格（典型：额度刚耗尽进冷却）→ 中止切换，保留原 `current`，输出原因，并记 `switch_aborted` trace。**不得自动改选第二名**（那等于换了一个用户没确认的目标）。
3. 原子写状态：`previous` ← 原 `current`；`current` ← 提案目标（含作用域别名、目标规范 id、意图类别、提案 id、时间）；清 `pending`。
4. 记 `model_switched` trace（§6.4），输出完成回显（含回滚提示）。

### 6.2 生效点

- 代理在每次 `plan()` 后读取切换状态（状态文件小、按 mtime 缓存即可，实现细节归 T3，但契约是：**确认执行后的下一个新请求即生效，无需重启服务**）。
- 生效方式即 §3.2 的置顶：该别名候选列表中置顶目标居首，其余顺序不变；置顶目标在该请求时不合资格 → 本请求按无置顶排序并在该请求的 trace 标注 `pin_skipped` 与原因。

### 6.3 失败回退

| 失败点 | 行为 |
|---|---|
| 状态文件写失败 | 切换不生效，报错并保留原状态（原子写：临时文件 + 改名，写一半不算数） |
| 状态文件损坏/不可解析 | 视为无置顶（回落正常排序）+ 告警输出；绝不因状态文件问题让代理崩溃 |
| 代理未运行 | 状态照常持久化，下次启动/下一个请求生效；执行回显中注明"网关未运行，切换将在下个请求生效"（以状态文件为唯一事实源，不依赖进程内通信） |
| 确认后目标漂移 | §6.1 第 2 步中止路径，不静默改选 |

### 6.4 与 PRD-201 trace 的打通

切换是**决策事件**而非请求，落 201 的 trace 体系（同一存储、同一查询面），事件类型与字段：

| 事件 | 触发 |
|---|---|
| `switch_proposed` | 提案生成 |
| `switch_confirmed` / `model_switched` | 确认并执行成功 |
| `switch_cancelled` | 取消/过期/交互答否 |
| `switch_aborted` | 执行时复检失败等中止 |
| `switch_rolled_back` | 回滚执行（§7） |

每条事件字段（口径与 201 的请求 trace 对齐：选中模型、成本、时间）：`ts`、事件类型、`alias`（作用域）、`from_target`、`to_target`、意图类别（只记类别枚举，**不记用户原话**——201 的既定口径是 trace 默认只存元数据）、预估成本快照（档位 + 剩余额度比例 + confidence）、提案 id、执行结果/中止原因。字段最终命名以 PRD-201/T1 定稿为准，T3 落地时对齐；若 201 的 trace 存储尚未落地，T3 先按本节字段落本地事件文件（与 `failover_decisions` 同库或同目录），201/T2 落地后并入，不阻塞 T3。

## 7. 回滚设计（为 T4 留的契约）

- **状态基础**：状态文件恒保存 `current` 与 `previous` 两槽（§8），回滚不需要额外历史设施。
- **语义**：回滚 = 交换 `current` 与 `previous`（回滚本身也可被回滚，天生可逆）；`previous` 为空（从未切换过）时回滚报错"无可回滚的上一后端"，状态不变。
- **确认门不减**：回滚同样走回显 + 确认两步，回显字段同 §5.2（目标后端即上一后端，预估成本按回滚时刻的实时信号重新估算，不复用旧快照）。
- **回滚到"无置顶"**：若 `previous` 是"无置顶"状态，回滚即清除置顶、恢复纯打分排序——这是合法且必须支持的目标状态。
- 回滚执行后记 `switch_rolled_back` trace；回滚不删除任何历史槽之外的数据（trace 即历史，本功能不另存多级历史；多级回滚为非目标）。

## 8. 状态存储契约

文件：`~/.open-free-router/model-switch.json`（沿用既有状态目录先例），权限 0600，原子写（临时文件 + 改名）。

```json
{
  "version": 1,
  "current":  {"alias": "<alias>", "target": "<provider>/<model>", "intent": "<类别>", "proposal_id": "<id>", "set_at": "<ISO 时间>"},
  "previous": {"alias": "<alias>", "target": "<provider>/<model 或 null>", "intent": "<类别>", "proposal_id": "<id>", "set_at": "<ISO 时间>"},
  "pending":  {"proposal_id": "<id>", "payload_hash": "<哈希>", "echo": {"...": "回显快照"}, "expires_at": "<ISO 时间>"}
}
```

- `target` 为 null 表示"无置顶"这一合法状态（`previous` 槽用它支持回滚到无置顶）。
- 同一时刻只允许一个 `pending`：新提案覆盖旧提案且旧确认码作废，回显中注明"已作废上一提案"。
- 状态文件只存元数据（别名、目标 id、类别、时间），不存密钥、不存用户原话。
- 作用域为多别名时，`current`/`previous` 按别名分键存储（上例为单别名示意）；T3 定稿 schema 时保持上述字段名与语义。

## 9. 红线落实清单

| 红线 | 设计层面的保证 |
|---|---|
| 不自动切换 | 唯一能写 `current` 的路径是 §6.1 执行步，其前置条件是有效确认码；failover、探测、同步等既有路径不引用切换状态的写接口（T3 须以测试证明：无确认码调用执行函数必被拒） |
| 未确认不切换 | 提案步与执行步分离（§5.1）；无 `--yes`；确认码与 payload 哈希绑定、单次有效、120 秒过期 |
| 误切换不伤在跑请求 | 切换只改变新请求的规划输入（§3.2、§6.2）；影响面在回显中逐字写明（§5.2） |
| 成本不编造 | 预估只给档位 + 实时比例，透传 confidence 与数据日期，固定偏差说明（§5.3）；禁止输出金额 |
| 不猜 | 歧义/无法解析/复合意图一律反问（§4.6）；执行时目标漂移中止而不改选（§6.1） |
| 不改 BYOS 接入层 | §10 边界；本功能对 registry 与 `byos.*` 配置只读 |
| 可回滚 | `previous` 槽恒保存（§7、§8），回滚走同一确认门 |

## 10. 与 PRD-173（BYOS 接入）的边界

- BYOS 接入层负责"接得进来"：provider 注册、`byos` 配置块、订阅类候选的识别与 `prefer_subscribed` 排序开关。本功能**只读**这些产物：候选池里有什么、各自 `byos_class` 是什么。
- 本功能负责"换得顺手"：在既有候选池内提名、确认、置顶、回滚。不新增 provider、不改 `byos.enabled`、不改 `prefer_subscribed`。
- 回显中出现 BYOS 类别标注只是信息展示，不构成对 BYOS 状态的任何修改。
- PRD-173 的在途 PR #84/#85（T4）与本设计无文件交集；本设计落地（T2 起）若与 BYOS 后续任务撞上 `routing.py`，以"不改变 BYOS 既有排序语义"为合并前提。

## 11. T2–T5 输入输出契约

### T2 意图解析（trend #1011）

- 输入：一句意图原话 + 上下文（现有别名清单、候选池快照、当前切换状态）。
- 输出：`IntentResult`——意图类别；作用域别名；`explicit` 时为目标规范 id；排序类意图为按 §4.3 权重档得到的提名列表（含各候选维度档位与分差）；或反问结构（原因枚举：`unknown` / `ambiguous` / `needs_choice` / `target_ineligible` + 可选项清单）。
- 验收锚点：PRD 示例与 §4.2 表格语句解析正确；§4.6 三种不猜路径有单测。

### T3 确认后切换执行 + trace 打通（trend #1012）

- 输入：§5 的提案 payload + 确认码。
- 输出：状态文件更新（§8 契约）；§6.4 的 trace 事件；执行/中止的回显。
- 硬性验收：未确认不切换（无确认码、错码、过期码、payload 被篡改四种情形均不得写 `current`，须有测试）；切换留 trace；§6.3 失败矩阵逐项有测试。

### T4 回滚（trend #1013）

- 输入：回滚意图（`switch rollback` 或 `rollback` 类别意图）。
- 输出：`current`/`previous` 交换后的状态 + `switch_rolled_back` trace + 回显确认全流程。
- 接口前提：只依赖 §7/§8 契约，不要求 T3 之外的任何内部结构；`previous` 为空与回滚到无置顶两种边界须有测试。

### T5 验收试运行（trend #1014）

- 输入：T2–T4 的完整链路 + 一组演练脚本（覆盖：三类排序意图、指定模型、歧义反问、确认过期、目标漂移中止、切换后新请求生效/在跑请求不受影响、回滚与回滚的回滚）。
- 输出：全链路演练记录（每步的回显与 trace 事件对照），结论可复核。

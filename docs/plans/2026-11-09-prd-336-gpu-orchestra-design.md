## 1. 借鉴对象、许可证与不复用红线

借鉴对象：dsx-ai-factory/nvke，**Apache-2.0（实测）**。

- **复用**：Apache-2.0 允许复用；但本设计**只借鉴「显存账本 + 换入换出顺序」的编排形态**。账本、调度建议、回退判据全部自研，落在本仓既有 hot_swap 状态机之上（编排器是 hot_swap 的**前置决策层**，不是第二套切换器）。
- **不引入**：原仓作为依赖；不接任何真实 GPU 驱动 API（与全仓「注入式探针」纪律一致——PRD-230 起就零设备调用，测试全 stub）。

## 3. GPU 账本设计

### 3.1 账本 schema（T2 预埋）

```json
{
  "schema": "gpu-ledger/v1",
  "gpus": [
    {"gpu_id": "gpu-0（占位）", "total_vram_mb": 24576,
     "reserved": {"model-a（占位）": 8192},
     "free_est": 16384}
  ],
  "models": [
    {"model": "model-a（占位）", "vram_mb": 8192, "gpu_id": "gpu-0（占位）",
     "state": "resident", "last_used_at": "…"}
  ]
}
```

- 账本是**声明式**：每模型的 `vram_mb` 由调用方注入（模型卡/实测值），编排器不探测——探测归既有探针；
- `free_est` = total − Σ reserved，只做算术，零猜测。

### 3.2 预留判定（§5 核心）

| 判定 | 规则 |
|---|---|
| 可直接换入 | `free_est >= target_vram_mb` → 建议 hot_swap(target) |
| 需先卸载 | free 不足但「卸掉某常驻模型后」满足 → 建议 `unload(victim)` + 序列化换入；victim 选择 = **最久未用且非当前健康在服模型**（LRU，确定性） |
| 无论如何都不满足 | `GPU_INFEASIBLE` 显形（目标模型显存需求 > 单卡总量），不硬换 |

## 4. 卸载顺序与回退判据（T3 落地）

### 4.1 卸载顺序（确定性）

1. 非当前在服模型优先（当前在服是回退底座，R2）；
2. 同为可卸 → LRU（last_used_at 最旧先卸）；
3. 同旧 → model_id 字典序（完全确定性）。

### 4.2 回退判据（R3，逐条定死）

| 判据 | 阈值（可配） | 动作 |
|---|---|---|
| 换入健康探针失败 | hot_swap 既有 retries 全败（§PRD-230 顺序） | 既有自动回滚（引用，不重实现） |
| 换入超时 | loading 阶段 > `LOAD_TIMEOUT_MS`（默认 120s） | 回退建议 + 显形 |
| 回退自身失败 | 原模型 load 也失败 | `failed` 显形（hot_swap 既有行为），编排账本记 `fallback_broken` 供人工介入 |

- 编排器收到回退结果后更新账本（victim 回到 reserved），全留痕。

### 4.3 与 hot_swap 的接线

```
编排器.plan(target) → {action: "hot_swap" | "unload_then_swap", victims, fallback_model, 判据表}
                     → 调用方按建议执行既有 hot_swap（编排器自己不执行）
                     → 执行结果回填账本（healthy/rolled_back）
```

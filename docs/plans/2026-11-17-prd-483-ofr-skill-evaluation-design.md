# PRD-483/T1：open-free-router 路由技能评估设计草稿

> 状态：设计草稿（T1），只设计不写代码；对应 trend issue：zhanglunet/trend#2335
> 来源：PRD-483《open-free-router 路由技能评估》；本批统一主题：技能要验收
> 借鉴：NVIDIA/SkillEvaluator（Apache-2.0）、Claude-BugHunter（MIT）、stitch-skills（Apache-2.0）——只借鉴思路，不复用代码

## 目标

给 open-free-router 的路由/网关 skill 包配一套评估：定期回答“这些路由技能还管用吗”。评估结果落账，过期/重叠/失效的技能进整改清单，不直接删。换路批准只审评估过关的技能出的建议。

## 一、质量门：阈值与判定口径（草稿，阈值由设计评审定，实测后复核）

质量门回答一个问题：技能是否真让 agent 少选错路。

- 判定口径（草稿）：
  - 错误路由率 = 选错后端/选错路的任务数 ÷ 有技能参与的路由任务总数；以有金标准（人工或历史正确路由）标注的任务为准。
  - 行为改变率 = 有技能 vs 无技能（ablation 对照）时路由决策发生变化且变对的任务占比；只变不变好不算过关。
  - 触发率与采纳率：技能被触发的任务占比、触发后 agent 实际采纳建议的占比；触发率过低（长期无人用）或采纳率过低（常被 agent 忽略）都记为失效信号。
- 阈值（草稿，待评审）：
  - 错误路由率 ≤ 5% 且不高于无技能对照组的 1/2；
  - 行为改变率 ≥ 10%（技能确实改变了行为，不是摆设）；
  - 采纳率 ≥ 80%，低于 50% 直接判失效进整改清单。
- 判定规则：三项中任一硬指标不达标即“未过关”，进整改清单；全部达标为“过关”；数据不足（样本 < 30 个任务）判“待补测”，不判过关也不判失效。
- 过期判定：技能引用的后端/配额/路由策略已变更（上游变了）而技能未同步更新，即判过期，进整改清单。

## 二、重叠检测方法

- 方法：技能两两比对——① 文本/语义相似度（触发条件、步骤、约束的 embedding 相似度，草稿阈值 ≥ 0.8 记候选重叠）；② 触发重叠率（同一任务同时触发两个技能的占比）；③ 产出重叠率（两个技能给出的路由建议一致的占比）。
- 判定：三项中有两项超阈值即判“重叠候选”，人工复核后确认；确认重叠的进整改清单（合并或拆分由整改定，不直接删）。
- 重点对：路由 skill 与配额 skill——两者都影响“走哪条路、花多少”，最容易重复教同一件事；另查路由 skill 之间互相重叠。

## 三、合成评测集：题源与证据要求

- 题源：造后端题考技能——题必须源自真实案例（Claude-BugHunter 式证据来源）：历史真实路由记录、真实换路决策、真实超预算/选错路事故；无来源的题不进评测集。
- 每道题必须带：题面（任务输入）、期望路由（金标准答案）、证据链接（真实案例出处）、适用技能（考的是哪个技能）。
- 题型覆盖：正常路由、后端故障切换、配额耗尽、成本敏感、延迟敏感五类；每类不少于 10 题，评测集总量不少于 50 题。
- 评测集版本化：每次新增/修改题目记版本号与变更原因；题目失效（对应后端已下线）即标记过期，不静默删除。

## 四、实测方案与行为变化度量

- 实测跑真实调度任务：在沙盒/影子模式下跑真实路由任务（不影响线上流量），对照组为无技能的 agent。
- 度量：错误路由率、行为改变率、采纳率（同质量门口径），另记成本变化（单任务平均成本）与延迟变化（p50/p95）；行为变化只认“变对”的部分，变错了记负分。
- 样本量：每轮实测不少于 100 个真实调度任务；结果与合成评测集结果交叉核对，不一致时以实测为准并记入报告。
- 频率：每轮评估出报告；技能包有变更（新增/修改技能）时加跑一轮。

## 五、评估结果落账与整改清单

- 每次评估产出评估报告落账：报告含每个技能的四项得分、过关/未过关/待补测结论、重叠候选清单、实测与评测集对照结果；报告 append-only，只增不改。
- 整改清单 append-only：过期/重叠/失效的技能进清单，记原因、证据、建议动作（修/合并/拆分）；评估结论绝不直接作为删除依据，技能下线另走审批。
- 闸门（T3 做）：评估未过关的技能不得进入下游——其路由建议不进换路批准流程。

## 六、与已有 PRD 的边界

- PRD-424（评审流水线审配置）：审产物（配置），本条评技能本身，不审产物。
- PRD-378（后端异常验证台）：验发现真假，本条验技能管不管用。
- PRD-364（收件箱）：管等人拍板，本条不管拍板流程。
- PRD-447（监督台）：人审 agent 干活的过程，本条不审过程、只量技能产出。
- 独立验收测试（PRD-012/022/034/037）：给单个 skill 写三层测试；本条评整个包的健康度，不给单个 skill 写测试。
- 不改技能包本身的形态与上架流程。

## 七、红线

- 学习网关只出推荐，不自动执行——评估不改变这一点，评估结果只进清单与报告。
- 只借鉴思路，不复用代码（SkillEvaluator / Claude-BugHunter / stitch-skills 均为思路借鉴）。
- 评估只进整改清单，绝不直接删技能；技能下线另走审批。

## 八、T2 交接要点

T2 按本设计实现最小版：质量门 + 重叠检测在真实技能包上跑通，产出首份评估报告落账。阈值以设计评审定稿为准，实测后复核调整。

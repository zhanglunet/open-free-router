# 找个免费可用的模型

## 30 秒速览

```bash
# 1. 确认代理在跑（没跑先起：bash scripts/install.sh --auto-discovery）
curl -s http://127.0.0.1:8337/health

# 2. 查现在可用的免费模型
curl -s http://127.0.0.1:8337/v1/models | python3 -c "import json,sys; [print(m['id']) for m in json.load(sys.stdin)['data']]"
```

看到模型列表 = skill 就绪。

## 怎么做

### 第 1 步：查可用模型

问代理要当前可用列表（只看 `available: true` 的）。如果用户点了名要某个模型
（如 deepseek），先查它在不在可用列表里。

### 第 2 步：智能路由

- 用户给了模型 ID → 按模型 ID 路由到对应上游。
- 用户给了虚拟模型（如 free-smart）→ 按虚拟模型路由。
- 用户只说"找个能用的"→ 选可解释评分最高的可用模型（调评分接口或看模型雷达）。

### 第 3 步：首字节前安全 fallback

主上游在首字节前失败 → 自动降级到备选上游（三层故障隔离）。
**必须**输出结构化切换原因，不要静默切换：

```json
{"from": "openrouter/deepseek-chat", "to": "groq/llama-3.3-70b", "reason": "首字节超时 8000ms", "at": "2026-10-17T10:00:00+08:00"}
```

## 什么时候不要用这个 skill

- 用户在讨论"模型"概念（如"大模型原理"）而不是要用模型干活时，不要触发。
- 用户明确指定了付费模型/API key 时，不要抢路由。

## 故障排查

| 现象 | 查什么 |
|---|---|
| 代理没在跑 | `curl 127.0.0.1:8337/health`，没通就起服务 |
| 所有模型都不可用 | 查实时探测状态（是否整批探测失败）；看最近 `probed_at` |
| 路由到了但很慢 | 查该模型的 `latency_ms`，换评分更高的 |
```

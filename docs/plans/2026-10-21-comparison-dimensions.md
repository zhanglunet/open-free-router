## 一句话

后续的对照页按**固定维度**、对**固定的四家**逐家成对来写。维度和名单在本任务定死；把格子填上字是后续任务，而且每一格都要能指回来源。

机器可读的源在：

- `docs/compare/dimensions.yaml` — 16 个维度、四组、单元格规则

两份 YAML 与本文档的 id 必须一致，`tests/test_comparison_catalog.py` 钉住这一点。增删维度或竞品要改这三处，不能只改页面。

## 单元格规则

这些规则写在 `dimensions.yaml` 的 `cell_rules`，后续填表时不得放宽。

1. **未知用 `unspecified`。** 页面上显示「资料未说明」。意思是所引资料没说，不是“没有”。
2. **填了的格子必须有来源。** 来源是对方官方页面或仓库，带标题和 `https` 链接。本仓库这一列引用本仓库。
3. **数字带核对日期。** 规模、版本、工具个数都要有 `snapshot_date`。两个口径冲突时并列，不取较大的一个。
4. **不打分，不设胜者列。** 没有总分，没有星级，枢纽页不按优劣排序。
5. **对照卡片每侧 3 条，而且只能压缩已经写在表里的维度。** 卡片不能引入表里没有的说法。本任务不写卡片正文。

## 维度

四组、16 行。主题是成对页的行名；问句是填格时要回答的那一件事。

### 定位与规模

| id | 行名 | 要回答的事 |
|---|---|---|
| `product` | 产品 | 它把自己定义成什么 |
| `who_runs_it` | 谁在运行 | 进程和数据默认在本机、自建服务器，还是厂商托管 |
| `source` | 源码 | 许可证、仓库是否公开 |
| `scale` | 规模口径 | 官方数字在数什么；口径不一致就并列 |
| `free_evidence` | 免费证据 | 免费层靠什么证明 |

### 接入、路由与韧性

| id | 行名 | 要回答的事 |
|---|---|---|
| `local_endpoint` | 本地端点 | 有没有本机统一入口 |
| `protocols` | 客户端协议 | 下游能说哪些协议 |
| `routing` | 路由 | 公开描述的选择方式 |
| `isolation` | 故障隔离 | 失败记在哪一层，有没有恢复路径 |
| `discovery` | 发现与接入 | 新提供商怎样才算可用 |

### 运维、评测与数据边界

| id | 行名 | 要回答的事 |
|---|---|---|
| `mcp` | MCP | 是否内置，资料有没有写明范围 |
| `evaluation` | 评测 | 质量证据和“能不能调通”是否分开 |
| `analytics` | 本地分析 | 记用量时是否默认保存 prompt |
| `public_status` | 公开状态 | 快照来自服务端、部署者监控，还是本机会话 |

### 安装与适用场景

| id | 行名 | 要回答的事 |
|---|---|---|
| `install` | 安装 | 运行栈和公开安装入口 |
| `audience` | 更适合谁 | 按目标描述取舍，不宣布赢家 |

这 16 行覆盖现有 `site/compare/index.html` 里已经在比的事项，改成成对页的行。没有新加“谁的星更多”这类维度。

纳入的四家就是现有矩阵的四列。本任务不给他们填格，只固定“谁有资格出现”，并记下后续核对要用的官方来源。
